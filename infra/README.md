# PolyEcho Infrastructure

This directory owns everything containerisation and deployment-related.
The packages themselves live in `packages/` — infra only builds and runs them.

## Quick Start

```bash
# 1. Copy and fill in secrets
cp .env.example .env

# 2. Start all services
bash scripts/dev.sh up

# 3. Run health check
bash scripts/dev.sh doctor

# 4. Apply DB migrations
pnpm db:migrate
# or via Docker:
docker compose -f infra/docker-compose.yml run --rm --profile tools cli polyecho db migrate

# 5. Tail logs
bash scripts/dev.sh logs
```

## Development Workflow (host stays clean)

```bash
# Drop into the all-in-one dev container (uv + pnpm, repo bind-mounted)
bash scripts/dev.sh dev

# Inside the container:
uv run pytest
uv run ruff check .
pnpm --filter @polyecho/web dev
```

## Build Context Notes

- **Python images**: build context is the **repo root** (required because uv
  workspace resolves all `packages/*/` relative to `pyproject.toml` at root).
- **Web image**: build context is also the **repo root** (pnpm workspace root).
- All `docker build` commands must be run from the repo root, or via compose
  (which sets the context automatically).

## Security Notes (PRD §4.2 / §7.2)

- `trader-core` holds the private key and exposes **zero ports**
- `db` binds to `127.0.0.1:5432` — never reachable from the network
- `dashboard-web` binds to `127.0.0.1:3000` — only accessible via Tailscale Serve
- The private key never enters the web or push images
- All containers run as non-root user `polyecho` (uid 1001)

## Reliability (PRD §7.3)

All long-running services use `restart: unless-stopped` so Docker automatically
restarts them after a crash or host reboot (requires Docker daemon to start on
boot — enable via Docker Desktop settings or `launchctl`).
