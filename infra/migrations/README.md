# Database Migrations

PolyEcho uses **Drizzle ORM** for database schema management. Migrations are
generated by the `@polyecho/web` package and stored in this directory.

## How It Works

The Drizzle config in `packages/web/drizzle.config.ts` is set up with:

```ts
out: '../../infra/migrations'   // points to this directory
```

This means all generated SQL migration files land here, versioned alongside
the infra code.

## Generating a Migration

After editing the Drizzle schema in `packages/web/lib/db/schema.ts`:

```bash
# From repo root
pnpm db:generate
# or directly:
pnpm --filter @polyecho/web db:generate
```

This compares the schema with the last migration and writes a new `.sql` file
into this directory.

## Applying Migrations

```bash
# From repo root (requires DB to be running)
pnpm db:migrate
# or directly:
pnpm --filter @polyecho/web db:migrate
```

Via Docker Compose (recommended for production):

```bash
docker compose -f infra/docker-compose.yml run --rm cli polyecho db migrate
```

Or directly against the running DB container:

```bash
docker compose -f infra/docker-compose.yml run --rm \
  -e POLYECHO_DB_URL_DRIZZLE=postgresql://polyecho:polyecho@db:5432/polyecho \
  web pnpm --filter @polyecho/web db:migrate
```

## Directory Contents

- `*.sql` — Drizzle-generated SQL migration files (committed to git)
- `meta/` — Drizzle internal snapshot directory (committed to git)
- `.gitkeep` — Ensures this directory exists even before the first migration
- `README.md` — This file

## Notes

- Never hand-edit generated `.sql` files
- Always generate migrations from schema changes, not raw SQL
- The Postgres DB name, user, and password are all `polyecho` (see `.env.example`)
- Connection URL for Drizzle uses the sync driver: `POLYECHO_DB_URL_DRIZZLE`
